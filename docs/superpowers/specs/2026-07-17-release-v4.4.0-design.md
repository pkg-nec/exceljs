# Release v4.4.0 of @pkg-nec/exceljs

**Date:** 2026-07-17
**Status:** Approved
**Goal:** Release `@pkg-nec/exceljs@4.4.0` to public npmjs.com — same functionality as `exceljs@4.4.0`, with metadata changes to establish it as a maintained fork, supply chain hardening, and CI modernization.

## Context

- Fork of [exceljs/exceljs](https://github.com/exceljs/exceljs), which has been unmaintained
- Origin remote: `https://github.com/pkg-nec/exceljs.git`
- `main` branch is at commit `ac96f9a` — the exact upstream v4.4.0 release commit
- `master` branch has 2 extra post-4.4.0 commits from upstream (pivot tables + bugfix), preserved as upstream reference
- No logic changes — this release is metadata, supply chain, and CI only
- npm scope `@pkg-nec` is already set up on npmjs.com

## Section 2: Supply Chain Hardening

### .npmrc

- Remove `package-lock=false`
- Add `min-release-age=7` — refuses to install any dependency version published less than 7 days ago (requires npm ≥ 11.10.0)

```diff
-package-lock=false
+min-release-age=7
```

### .gitignore

Remove the `package-lock.json` entry so the lock file is tracked in version control.

```diff
-package-lock.json
```

### package-lock.json

Generate via `npm install` (one-time, locally with npm 11.10.0) and commit it. This lock file ensures reproducible installs via `npm ci`.

## Section 3: CI Modernization

### .github/workflows/tests.yml

Full list of changes:

1. **Branch trigger:** `push: branches: [master]` → `push: branches: [main]`
2. **All `npm install` → `npm ci`** across all 3 jobs (test, benchmark, typescript)
3. **GitHub Actions versions:**

   | Action | Before | After |
   |--------|--------|-------|
   | `actions/checkout` | v2 (pinned SHA) | `v7` |
   | `actions/setup-node` | v2 (pinned SHA) | `v7` |
   | `actions/cache` | v2 (pinned SHA) | `v6` |

4. **Node.js version matrix:** `[10.x, 12.x, 14.x, 16.x, 17.x, 18.x, 19.x, 20.x]` → `[18.x, 20.x, 22.x, 24.x]`
5. **Pin npm version:** Add `npm install -g npm@11.10.0` step before `npm ci` in each job, so `min-release-age` is recognized and the lockfile format stays consistent across environments
6. **Cache key:** `hashFiles('**/package.json')` → `hashFiles('**/package-lock.json')` (lock file now exists and is the correct cache-bust signal)
7. **typescript job:** Remove the separate `npm install typescript` step — typescript is already in `devDependencies`, `npm ci` installs it
8. **Remove manual cache directory creation** — the `mkdir npm-cache && npm config set cache ./npm-cache --global` pattern is obsolete with modern `actions/cache@v6` and `actions/setup-node@v7`

## Section 4: Build, Tag & Publish

All implementation work is done on a feature branch (`release/4.4.0`), merged to `main` before tagging and publishing.

Release sequence (executed locally):

1. Create branch `release/4.4.0` from `main`
2. Commit all changes from Sections 1–3 on `release/4.4.0`
3. `npm install` — generates `package-lock.json` (one-time, using npm 11.10.0)
4. Commit `package-lock.json`
5. `grunt build` — produces `dist/` browser bundle (required: `files` in package.json includes `dist`)
6. `npm test` — verify nothing is broken
7. Merge `release/4.4.0` into `main`
8. `git tag v4.4.0` — tag the merge commit on `main`
9. `git push origin main --tags` — push commits and tag
10. `npm publish --access public` — publish to npmjs.com (scoped packages require `--access public` on first publish)
